# 13_Reports

This folder contains sample reporting artifacts that show how passed and failed tests would be presented after execution. Runtime reports are generated by Maven/TestNG/Cucumber under `target/`, while this folder provides static examples for GitHub review.

## Report outputs included

- `Sample-Test-Execution-Summary.md`: Human-readable pass/fail summary.
- `sample-testng-results.xml`: TestNG/JUnit-style XML showing passed and failed tests.
- `sample-cucumber-report.json`: BDD scenario result sample.
- `sample-failed-test-log.txt`: Example failure log for defect triage.
- `ReportArtifactReader.java`: Small Java example showing how a utility could read report files.

## Runtime report locations

```text
target/surefire-reports/          TestNG/JUnit XML and text results
target/cucumber-reports/          Cucumber HTML and JSON results
target/failed-test-screenshots/   Selenium screenshots captured on failures
```


## Browser-Based Report Review

A simple static web dashboard is included here:

```text
13_Reports/web-ui/index.html
```

Open it directly in a browser or run:

```bash
./scripts/open-report-ui.sh
```

Then open:

```text
http://localhost:8080
```

## Typical Enterprise Reporting Options

SDET teams typically review automated test results through one or more of these interfaces:

- Jenkins / CloudBees build report pages
- JUnit/Surefire XML trend reports
- Cucumber HTML reports
- Allure Reports
- Extent Reports
- GitHub Actions artifacts
- HTML Publisher Plugin in Jenkins

This repository includes static sample reports with both passing and failing tests for GitHub review. After running Maven, live reports are generated in `target/surefire-reports/`, `target/cucumber-reports/`, `target/failed-test-screenshots/`, and `target/visual-snapshots/`.

## Selenide Report Output

Selenide automatically stores screenshots and page source snapshots when a test fails. This project configures the report folder in `SelenideTestBase`:

```java
Configuration.reportsFolder = "target/selenide-reports";
Configuration.screenshots = true;
Configuration.savePageSource = true;
```

Typical artifacts after execution:

```text
target/selenide-reports/
|-- SelenideOrderLifecycleTest_userCanLoginSelectCatalogueItemCheckoutAndPay.png
|-- SelenideOrderLifecycleTest_userCanLoginSelectCatalogueItemCheckoutAndPay.html
`-- browser-log.txt
```

The sample `13_Reports/sample-selenide-testng-results.xml` contains both pass and intentional failure examples so reviewers can see how success/failure status appears in CI reports.

## Allure Web UI Reports

The preferred browser-based report viewer for this project is Allure. Use it locally or through GitHub Actions/GitHub Pages.

Local generation:

```bash
mvn clean test -Pallure-ui -Dallure.results.directory=target/allure-results
mvn allure:report
open target/site/allure-report/index.html
```

GitHub UI generation:

1. Push the project to GitHub.
2. Open **Actions**.
3. Run **Selenium CI/CD Pipeline with Allure Reports**.
4. Download raw artifacts or open the published GitHub Pages dashboard.

Sample Allure result JSON files are stored in `13_Reports/allure-sample-results/` so reviewers can see the pass/fail data shape used by the Allure dashboard.
